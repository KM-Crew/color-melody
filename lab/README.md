# lab — 사진 → 소리 시험 코드 (P5, 2026-11-24)

## 3줄 요약

1. 사진 분석(`analyze.js`) → 곡 설정값·작곡(`compose.js`) → 재생·WAV 굽기(`render.js`)를 **본 앱과 따로** 만들었고, `index.html` 에서 사진을 넣고 **D(분위기+스캔) / B(스캔만) / A(지금 방식)** 를 번갈아 들을 수 있다.
2. 자동 테스트는 **전부 통과**했다: node 46항목(`test/run.js`), 헤드리스 Chromium 158로 PC 1280px·모바일 390px 각 16항목(`test/browser.js`) — P6에서 링크 글자열 항목을 더한 수. 03 문서 5절의 기준(음계 밖 음 0, 길이 15~30초, 그림 쌍 차이 최소 0.10·중앙값 0.30, 극단 입력)을 그대로 넣었다.
3. **소리를 귀로 들어 보지는 못했다**(헤드리스 환경). 확인한 것은 "무음이 아님·찢어지지 않음·길이"까지다. 듣기 좋은지, 악기 음색이 괜찮은지는 사람이 `index.html` 을 열어 확인해야 한다.

## 제작에 주는 결론

- 세 모듈은 DOM 없이 도는 순수 함수(재생 제외)라서 본 앱에 **파일째 옮겨 쓸 수 있다.** 전역 이름은 `LabAnalyze`·`LabCompose`·`LabRender`(브라우저), node 에서는 `require`.
- 흐름은 **픽셀 → 특징(JSON) → 곡 설정값(구간 값만) → 음표 목록 → 소리** 로 고정한다. 작곡은 설정값만 본다 → 공유 링크에 설정값(`#seed` 에 보이는 JSON, 시험 그림 14장에서 221~260자·평균 약 240자)을 담으면 받는 쪽이 같은 곡을 듣는다. 링크용 짧은 글자열은 P6에서 `seedlink.js` 로 만들었다(51~79자, [BUILD_SPEC](../docs/prep/BUILD_SPEC.md) 5-3절).
- 방식 D만 "겹치는 곡 0쌍"이었다(시험 그림 14장, 91쌍). B는 5쌍, A는 3쌍이 거의 같고 A는 흑백·바둑판·파스텔에서 빈 곡이다 → **D를 기본으로 제작**해도 된다는 P3 추천을 숫자로 다시 확인했다(청취 확인은 남음).
- 사진 축소는 **2단계(긴 변 512 → 분석 크기)** 를 기본으로 뒀다. 4000×3000 시험 그림에서 1단계와 2단계의 설정값이 멜로디 16칸 중 1칸 달랐다 → 축소 방법을 중간에 바꾸면 같은 사진의 곡이 달라질 수 있으니 **한 번 정하면 바꾸지 않는다.**
- 구간 경계(`compose.js` 의 `CUT`)는 **시험 그림 14장에 맞춘 초안**이다. 실제 사진에서 한쪽에 쏠리는지는 확인 못 함 → 사람이 자기 사진 10장을 넣어 "자세히: 사진에서 읽은 값"을 보고 조정.

## 파일

| 파일 | 내용 |
|---|---|
| `analyze.js` | `analyze({data, width, height})` → 특징 JSON(02 문서 6절 형식). 긴 변 128로 줄이기(`shrink`), 팔레트+비율, 밝기·대비·채도·따뜻함, 가장자리 밀도, 세로줄 16칸, 3×3 칸, 눈에 띄는 곳, flags. 소수 3자리 반올림 |
| `compose.js` | `toSeed(특징)` → 곡 설정값, `compose(설정값, 'D'｜'B'｜'A')` → 음표 목록, `explain(설정값)` → 설명 문장, `signature`·`distance` → 차이 지표(03 문서 4-2절) |
| `render.js` | `play(ctx, 곡)` 실시간 재생, `renderOffline(곡)` 굽기, `wavBytes(표본, 표본율)` 16비트 모노 WAV, `measure` 점검용. 합성 악기 6종(피아노풍·벨·플럭·패드·베이스·하이햇) + 컴프레서 + 직접 만든 잡음 잔향 |
| `seedlink.js` | (P6 추가) `encode(설정값)` → 링크용 글자열(`0-9a-z-`, 51~79자), `decode(글자열)` → 설정값 또는 `null`. 형식은 [BUILD_SPEC](../docs/prep/BUILD_SPEC.md) 5-3절 |
| `index.html` | 비교 청취 페이지. 사진 고르기·끌어다 놓기·붙여넣기, 시험 그림 14개, 방식 3개, 재생 막대, WAV 저장, 설명·팔레트·특징 값·설정값 표시. PC 2단·모바일 1단 |
| `samples/make.js` | 시험 그림 14장 생성기(브라우저·node 공용). `node lab/samples/make.js` → PNG 14장(384×288) 다시 만들기 |
| `samples/*.png` | 위 스크립트가 만든 그림(남의 사진 아님). 파일 선택 경로 시험과 사람이 보는 용도 |
| `test/run.js` | node 테스트(분석·작곡·WAV) |
| `test/browser.js` | 헤드리스 브라우저 테스트(비교 페이지) |
| `bench/` | P2~P4 측정 코드(그대로 둠) |

## 방식 D 가 실제로 하는 일 (03 문서 6-2절 대비 달라진 점 포함)

| 곡 요소 | 규칙(구현) | 03 초안과 다른 점 |
|---|---|---|
| 조 | 가장 넓은 대표색의 색상 30도마다 5도권 순서 12조, 흑백이면 A. 으뜸음은 C4±6반음 안으로 접음 | 벤치는 6조 → 12조 |
| 장·단조 | 기분값(0.69×밝기+0.22×채도+0.1×따뜻함) 경계 0.2/0.36/0.52 중 위 2구간 = 장조 | 균등 4구간(0~0.8) → 시험 그림에 맞춘 경계 |
| 리듬 | 가장자리 밀도 경계 0.01/0.05/0.12/0.25 → 0~4단계. 단색(`flat`)이면 0 | 균등 5구간 → 낮은 쪽을 잘게(균등이면 0과 4에만 몰림) |
| 빠르기 | (리듬 단계 + 채도 5구간) 평균 → 72/84/96/108/120 | 같음. 14장에서 72·84·96·120 네 값이 나옴(108은 안 나옴) |
| 음역 | 밝기 0.3 / 0.62 경계 → −1/0/+1 옥타브. 멜로디는 48~91 안으로 접음 | 03의 "C4~C6"보다 넓힘(음역 차이가 들리게) |
| 화음 진행 | 대표색 1~2개(또는 단색) → I–IV–V–I, 3~4개 → I–V–vi–IV, 5개 → I–vi–IV–V (단조는 같은 자리의 단조 진행). **7마디는 끝맺는 화음, 8마디는 으뜸화음** | 7·8마디 규칙을 추가 |
| 멜로디 | 세로줄마다 `lift` 5구간 + 밝기 4구간 = 0~7 → 5음계 위치. 마디당 2칸. 칸 안의 둘째·셋째 음은 다음 칸 쪽으로 한두 음 움직임. 센박은 화음 구성음으로 맞춤 | 칸 안 움직임 규칙을 추가 |
| 세기 | 세로줄 채도 3구간 × 구간(도입·전개·마무리) × 센박/약박 → 소수 2자리 | 연속 값 → 구간 값(P3가 넘긴 고칠 점) |
| 편곡 | 도입 2마디는 패드+멜로디만, 전개 4마디에 베이스(+채도 높으면 반짝임, 리듬 3 이상이면 하이햇), 마무리 2마디는 리듬 2단계 낮춤, 8마디째 으뜸음 길게, 여운 최대 2초 | 03 1-4절 그대로 |
| 절정 | 4~11번째 칸 중 밝기×(0.2+채도)가 가장 큰 칸의 센박에서 한 옥타브 위 1번 | 03은 밝기×채도 → 흑백에서도 고를 수 있게 0.2를 더함 |
| 악기 | 따뜻함 −0.06 / 0.12 경계 → 벨 / 피아노풍 / 플럭. 아주 어두우면 벨. 채도 3구간 이상이면 패드 필터를 엶 | 같음 |

## 확인 못 한 것

- **실제로 들은 평가 전부**(듣기 좋음, 악기 음색, 음량 균형, D/B/A 중 무엇이 나은지). `render.js` 의 수치는 03 문서 1-5절 설계안 그대로다.
- **실제 사진**에서의 결과(남의 사진을 쓰지 않아 코드로 그린 그림만 시험). 시험 그림은 가장자리 밀도가 0 아니면 0.2 이상으로 극단적이라 실제 사진 분포와 다를 수 있다.
- **실기기**(아이폰 무음 스위치, 인앱 브라우저, 휴대폰에서 곡 전체를 한꺼번에 예약할 때의 부하). 04 문서 6절 점검표를 이 페이지로 수행하면 된다.
- 끌어다 놓기·붙여넣기는 코드만 넣었고 자동 테스트하지 않았다(파일 선택 경로만 시험).
