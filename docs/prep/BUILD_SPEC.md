# 제작 설계서 — 색의 노래 (사진 → 소리) (2026-11-24)

## 3줄 요약

1. 만들 것: **사진 한 장을 넣으면 15~30초짜리 곡이 나오고, 왜 그런 소리인지 보여 주고, 링크로 보낼 수 있는 웹.** 로그인·설치·서버 없음, PC·모바일 공용. 변환 방식은 **D(분위기가 틀을 정하고 좌→우 스캔이 멜로디)** 로 한다.
2. 분석·작곡·재생·링크 부호화 모듈은 **이미 `lab/` 에 있고 테스트를 통과한다**(node 46항목, 헤드리스 브라우저 PC·모바일 각 16항목). 본 제작은 "새 화면 3개(첫 화면·결과·받은 노래) + 모듈 연결 + 공유"가 전부다.
3. 일정은 11/25~11/28 제작, **11/29 여유**, 11/30 낮 제출. 가장 큰 미확인 위험은 **아무도 소리를 들어 보지 못했다는 것**과 **실기기(아이폰 무음 스위치·카카오톡 인앱)** 이다 → 제작 첫날 사람이 30분 써서 확인한다([HANDOFF](HANDOFF.md) 2절).

## 제작에 주는 결론

- **기존 앱을 갈아엎지 않는다.** `app.js` 의 카메라 색 모으기와 옛 링크(`#/play?c=`)는 그대로 두고, 새 화면을 **새 파일 `photo.js`** 에 만든다. 고치는 기존 파일은 `index.html`(스크립트 4줄·메타 문구)과 `app.js` 의 첫 화면(`Router.on('/')`) 한 곳뿐이다. `core.js`·`core.css` 는 고치지 않는다(10개 저장소 공용).
- **`lab/` 의 네 모듈을 `song/` 폴더로 옮겨 그대로 쓴다**(복사하지 않는다 — 원본이 둘이면 "같은 사진 = 같은 노래"가 깨질 수 있다). 테스트(`lab/test/`)는 경로만 고쳐 계속 돌린다.
- **공유의 기본은 링크**다. 링크에는 사진이 아니라 **곡 설정값(51~79자)** 이 들어간다(5-3절, 구현·테스트 끝남). 받는 사람은 사진 없이 같은 곡을 듣는다.
- **첫 화면에 예시 그림 3개**를 둔다(사진을 고를 수 없는 환경에서도 체험이 0에서 막히지 않게).
- 영상 내보내기·얼굴 인식·AI 생성은 **넣지 않는다**. 그림 카드·WAV 저장은 시간이 남으면(10절 순서대로).

이 문서에서 **"확인됨"** 은 이 저장소의 테스트나 직접 측정으로 본 것, **"미확인"** 은 사람·실기기 확인이 남은 것이다. 근거 문서: [01 사례](01-prior-art.md) · [02 분석](02-image-analysis.md) · [03 소리](03-sonification.md) · [04 호환성](04-compat.md) · [lab 결과](../../lab/README.md).

## 2. 30초 체험 흐름

| 시각 | 사용자가 하는 일 | 화면이 하는 일 |
|---|---|---|
| 0초 | 첫 화면을 본다 | 한 줄 소개, 큰 버튼 **[사진 고르기]**, 그 아래 **예시 그림 3개**(누르면 바로 곡), "사진은 기기 밖으로 나가지 않아요" |
| ~5초 | 사진을 고른다(또는 예시를 누른다) | 분석(0.1초 안, 확인됨: 4000×3000 JPEG 고르기→곡 준비 82~93ms, 헤드리스 PC) → 결과 화면으로 |
| ~7초 | **[▶ 듣기]** 를 누른다 | 사진 위로 **막대가 왼쪽→오른쪽**으로 지나가고, 아래 16칸 띠에서 지금 칸이 커지고, "♪ 지금 음" 이 바뀐다 |
| ~15초 | 듣는다 | 설명 카드 3~4줄이 사진 옆(모바일은 아래)에 보인다: "밝고 선명한 사진이라 환한 느낌의 음계를 골랐어요" 등 |
| ~25초 | 곡이 끝난다 | **곡 제목**(예: "환한 산책")과 **[링크로 보내기]**·**[다른 사진 넣기]** 가 강조된다 |

- 예시를 누른 경우는 그 누름이 곧 사용자 동작이라 **바로 재생**한다. 사진을 고른 경우는 브라우저가 자동 재생을 막을 수 있으므로 재생을 시도하고, 소리 장치가 `running` 이 아니면 큰 ▶ 버튼을 보여 준다([04 문서](04-compat.md) 제작 결론).
- 하나의 곡은 18.0~28.7초(확인됨, 시험 그림 14장). 반복 재생은 기본 끔.

## 3. 화면 구성

경로는 지금 `core.js` 라우터(`#/경로?값`)를 그대로 쓴다.

| 경로 | 화면 | 상태 |
|---|---|---|
| `#/` | 첫 화면(사진 고르기) | **새로 씀**(`app.js` 의 첫 화면을 대체) |
| `#/song` | 내 사진의 노래(결과) | **새로 만듦**(`photo.js`). 사진은 메모리에만 있어 새로고침하면 첫 화면으로 |
| `#/song?s=<글자열>` | 받은 노래(사진 없음) | **새로 만듦**. 같은 화면에서 사진 자리에 "색 악보 그림"(3-3절) |
| `#/collect`, `#/compose` | 카메라로 색 모으기·연주 | **그대로 둠**. 첫 화면 맨 아래 작은 링크 "색을 하나씩 모아서 만들기" |
| `#/play?c=…` | 옛 공유 링크 | **그대로 둠**(이미 보낸 링크가 계속 열려야 함) |

### 3-1. 첫 화면 `#/`

| 요소 | PC(폭 900px 이상, 2단) | 모바일(1단) |
|---|---|---|
| 제목·한 줄 소개 | 왼쪽 단 위 | 맨 위 |
| **[사진 고르기]** (`<input type="file" accept="image/*">` 를 감싼 큰 버튼) | 왼쪽 단. 그 둘레가 **끌어다 놓는 자리**(점선 테두리, "여기에 사진을 끌어다 놓거나 Ctrl+V") | 화면 폭 가득한 버튼 하나. 끌어다 놓기 문구는 숨김 |
| 예시 그림 3개(노을·숲·야경, `lab/samples/make.js` 가 그린 그림) | 버튼 아래 한 줄 | 버튼 아래 한 줄(가로 3칸) |
| 안심 문구 | "사진은 이 기기 안에서만 읽어요. 어디에도 올리지 않아요." | 같음 |
| 이렇게 바뀌어요(3줄) | 오른쪽 단 카드: "분위기 → 음계와 빠르기 / 왼쪽에서 오른쪽으로 읽은 흐름 → 멜로디 / 따뜻하고 차가운 색 → 악기" | 아래 카드 |
| 보조 링크 | "색을 하나씩 모아서 만들기 →"(`#/collect`) | 같음 |

- `capture` 속성은 넣지 않는다(넣으면 보관함을 못 고른다). `image/heic` 도 넣지 않는다([04 문서](04-compat.md) 7절).
- 붙여넣기(`paste`)·끌어다 놓기(`drop`)는 PC 편의 기능. `lab/index.html` 에 코드가 있으나 **자동 테스트는 안 됨**(미확인).

### 3-2. 결과 화면 `#/song`

| 요소 | PC(2단) | 모바일(1단, 위→아래) |
|---|---|---|
| 사진(긴 변 1280 이하로 그린 캔버스) + **스캔 막대** | 왼쪽 단, 높이는 화면의 60% 안 | ① 폭 가득, 높이 45vh 안 |
| 16칸 색 띠(세로줄 대표색, 지금 칸 강조) | 사진 바로 아래 | ② |
| **[▶ 듣기 / ■ 멈춤]** + "♪ 지금 음" | 오른쪽 단 맨 위 | ③ 사진 아래 큰 버튼. 스크롤해도 **화면 아래에 붙어 있음**(sticky) |
| 곡 제목 + 한 줄 요약("라 단조 · 느리게 · 종소리") | 오른쪽 단 | ④ |
| **설명 카드 3~4줄**(왼쪽에 색 조각, 오른쪽에 문장) + "자세히"(숫자·용어) | 오른쪽 단 | ⑤ |
| 공유: **[링크로 보내기]** [링크 복사] (+ [그림 카드 저장] [소리 파일 저장]은 2차) | 오른쪽 단 아래 | ⑥ |
| [다른 사진 넣기] | 오른쪽 단 맨 아래 | ⑦ |

- 키보드: Space = 듣기/멈춤(지금 연주 화면과 같음), Tab 순서는 듣기 → 공유 → 다른 사진. 포커스 표시는 `core.css` 것을 쓴다.
- `prefers-reduced-motion` 이면 막대·강조의 움직임을 줄이고 소리는 그대로(지금 `Motion` 도우미).
- 화면을 벗어나면(`visibilitychange`) 재생을 멈추고, 돌아와도 자동으로 다시 틀지 않는다.
- 가로·세로 전환 때 막대 위치는 **곡 시각에서 다시 계산**한다(픽셀 위치를 저장하지 않는다).

### 3-3. 받은 노래 `#/song?s=…`

- 사진은 오지 않는다. 사진 자리에 **색 악보 그림**을 그린다: 가로 16칸, 칸마다 멜로디 높이(0~7)만큼 올라간 막대, 색은 링크에 담긴 대표색 1~5개를 차례로. 스캔 막대는 같은 방식으로 지나간다.
- 맨 위 안내: "누군가 사진으로 만든 노래예요. 사진은 오지 않고 색과 노래만 왔어요." 버튼: [▶ 듣기] / **[내 사진으로도 만들기]**(`#/`).
- 설명 카드·곡 제목은 설정값에서 다시 만든다(같은 문장이 나온다).

### 3-4. 빈 상태·오류 상태

| 상황 | 화면 |
|---|---|
| `#/song` 에 사진이 없음(새로고침, 직접 주소 입력) | 첫 화면으로 보낸다(토스트 없음) |
| 열 수 없는 파일(HEIC·그림 아님) | "이 사진 형식은 열 수 없어요. 화면을 캡처해서 넣어 보세요." + 예시 그림 버튼(확인됨: `lab/index.html` 의 같은 처리, 오류 없음) |
| 받은 링크가 깨짐(`decode` 가 `null`) | "노래 링크가 깨졌어요. 사진으로 새로 만들어 보세요" → 첫 화면(확인됨: 깨진 글자열 17종 모두 `null`) |
| 소리 장치가 안 켜짐(`state !== 'running'`) | 막대와 시각화는 움직이고 "소리가 안 들리면 ▶를 한 번 더 눌러 주세요" |
| 아이폰 | 재생 버튼 아래 한 줄 "소리가 안 들리면 옆면 무음 스위치를 확인해 주세요"(실기기에서 필요 없다고 확인되면 뺀다) |
| 인앱 브라우저에서 파일 저장을 누름 | 저장을 시도하지 않고 "카카오톡 안에서는 파일 저장이 안 될 수 있어요. 링크를 복사해 다른 브라우저에서 열면 같은 노래가 나와요" + [링크 복사] |
| 단색·흑백·아주 어두운 사진 | 오류가 아님. 곡이 나오고 설명 문장이 바뀐다("색이 거의 없는 사진이라…") |
| 허브(iframe) 안 | 새 창을 열지 않는다(AGENTS.md). 공유가 막히면 링크를 글자로 보여 준다(지금 `shareText` 의 마지막 단계) |

## 4. 모듈 구조

```
index.html          스크립트 4줄 추가, 제목·메타 문구 변경
core.js / core.css  고치지 않음
app.js              첫 화면 등록(Router.on('/'))만 떼어 냄. 나머지(색 모으기·연주·옛 링크)는 그대로
photo.js   (새로)   첫 화면 · 결과 · 받은 노래 화면, 사진 읽기, 재생 조작, 공유, 곡 제목
style.css           새 화면용 규칙을 아래에 덧붙임
song/      (lab/ 에서 git mv)
  analyze.js        픽셀 → 특징 JSON                    전역 LabAnalyze
  compose.js        특징 → 곡 설정값 → 음표, 설명 문장   전역 LabCompose
  render.js         음표 → 재생, 굽기, WAV               전역 LabRender
  seedlink.js       곡 설정값 ↔ 링크 글자열              전역 LabSeedLink
  samples.js        예시 그림 생성기(lab/samples/make.js) 전역 LabSamples
lab/                비교 청취 페이지·테스트·측정 코드(스크립트 경로만 ../song/ 으로)
```

- 전역 이름(`Lab…`)은 바꾸지 않아도 된다. 바꾼다면 한 번에 바꾸고 테스트를 돌린다.
- 스크립트 순서: `core.js` → `song/*.js` → `app.js` → `photo.js`. `photo.js` 가 `Router.on('/')` 과 `Router.on('/song')` 을 등록하고, `Router.start` 는 맨 마지막에 한 번만 불리게 `app.js` 끝의 호출을 `photo.js` 끝으로 옮긴다.
- 외부 요청: 지금 `index.html` 이 부르는 글꼴(Pretendard)·html2canvas CDN은 그대로 두되 **새 화면은 그것 없이도 동작**해야 한다(그림 카드는 캔버스로 직접 그린다, 7절). 확인됨: `lab/index.html` 은 외부 요청 0.

### 4-1. `photo.js` 가 맡는 일 (lab 에서 가져올 코드)

| 일 | `lab/index.html` 의 참고 함수 | 지킬 것 |
|---|---|---|
| 사진 읽기 → 픽셀 | `loadFile`, `pixelsOf`(2단계 축소: 긴 변 512 → 128) | **축소 방법을 바꾸지 않는다**(1단계와 멜로디 1칸 차이, 확인됨). 원본 크기 캔버스를 만들지 않는다 |
| 표시용 그림 | `showOnView`(긴 변 1280 이하) | 분석용과 따로 그린다 |
| 소리 시작 | `ensureCtx` | 버튼 누름 안에서 `AudioContext` 만들기/`resume()`. `webkitAudioContext` 대비. 아이폰은 `navigator.audioSession.type = 'playback'`(있을 때만) |

## 5. 데이터 형식

흐름은 고정이다: **픽셀 → 특징 → 곡 설정값 → 음표 목록 → 소리.** 작곡은 설정값만 본다.

### 5-1. 특징(분석 결과)

`LabAnalyze.analyze({data, width, height})` 의 결과. 형식은 [02 문서](02-image-analysis.md) 6절, 구현은 `lab/analyze.js`. 본 앱에서 직접 쓰는 것은 `palette`(색 띠), `layout.columns[].hex`(16칸 띠) 정도이고 나머지는 `toSeed` 에 넘긴다.

### 5-2. 곡 설정값

`LabCompose.toSeed(특징)` 의 결과. 모든 값이 구간 값(정수·낱말)이다.

| 필드 | 값 | 뜻 |
|---|---|---|
| `v` | 1 | 형식 판 |
| `key` | 0~11 | 으뜸음(0=도) |
| `mode` | `maj` / `min` | 장조·단조 |
| `bpm` | 72·84·96·108·120 | 빠르기 |
| `register` | −1·0·1 | 음역 |
| `rhythm` | 0~4 | 리듬 밀도 |
| `prog` | 0~2 | 화음 진행 |
| `lead` | `piano`·`bell`·`pluck` | 멜로디 악기 |
| `pad` | 0·1 | 패드 필터 열림 |
| `dyn` | 0~2 | 셈여림 폭 |
| `peak` | 4~11 | 절정 칸 |
| `gray` | 0·1 | 흑백 사진 |
| `melody` | 0~7 × 16 | 세로줄 16칸의 멜로디 위치 |
| `vel` | 0~2 × 16 | 세로줄 16칸의 세기 |
| `colors` | 6자리 색 1~5개 | 대표색(화면용, 조는 이미 `key` 에 반영) |

### 5-3. 링크 글자열 (구현·테스트 끝남: `lab/seedlink.js`)

```
1 51210021140 5566666555555555 2211112222222222 -c85763-972876-e79957
│ └ 머리 11자  └ 멜로디 16자     └ 세기 16자       └ 색 1~5개
└ 형식 판            (시험 그림 '노을'의 실제 값. 보기 좋게 띄어 썼고 실제로는 붙여 쓴다)
```

- 머리 11자는 순서대로 `key`(36진수 0~b), `mode`(0=min, 1=maj), `bpm` 순번(0~4), `register`+1, `rhythm`, `prog`, `lead` 순번(piano·bell·pluck), `pad`, `dyn`, `peak`(4~b), `gray`.
- 쓰는 글자는 `0-9a-z-` 뿐이고 길이는 **51~79자**(확인됨). 전체 주소 예(노을): `https://km-crew.github.io/color-melody/#/song?s=15121002114055666665555555552211112222222222-c85763-972876-e79957`.
- `decode` 는 정규식과 범위 검사를 통과하지 못하면 **`null`** 을 돌려준다(확인됨: 깨진 글자열 17종). 형식에 맞는 **임의의 글자열 200개**로 만든 곡도 음계 밖 음 0, 길이 15~30초였다(확인됨) → 누가 링크를 손으로 고쳐도 이상한 소리는 나지 않는다.
- 받은 값은 화면에 넣을 때 색(`#` + 6자리 16진수)과 숫자로만 쓴다. 링크의 글자를 HTML 로 그대로 넣지 않는다.
- 형식을 바꿀 일이 생기면 맨 앞 판 글자를 `2` 로 올리고 `1` 도 계속 읽는다.

### 5-4. 음표 목록

`LabCompose.compose(설정값, 'D')` → `{ bpm, seconds, scanSeconds, events: [{ t, dur, midi, vel, inst }] }`. `t`·`dur` 는 박 단위. `inst` 는 `lead`(멜로디)·`pad`·`bass`·`hat`·`spark`(반짝임) 다섯 가지(`lab/compose.js`). `lead` 의 실제 음색은 설정값의 `lead` 필드가 정한다. 본 앱은 **D만** 쓴다. B·A는 `lab/` 비교 페이지에만 남긴다.

## 7. 결과 공유 설계

목표는 **받은 사람이 눌러서 듣고, 자기 사진으로도 해 보는 것**이다(투표는 체험 후 별점+리뷰).

| 순위 | 공유물 | 내용 | 동작 환경 | 일정 |
|---|---|---|---|---|
| 1 | **링크** | 곡 설정값이 든 주소. 문구: "내 사진이 '환한 산책'이라는 노래가 됐어. 들어 볼래?" | 전부(공유 시트 → 복사 → 글자로 보여 주기, 지금 `shareText`) | **필수** |
| 2 | **곡 제목** | 설정값에서 고른 두 낱말(아래 표). 공유 문구·결과 화면·그림 카드에 쓴다 | — | **필수**(규칙 표만 있으면 됨) |
| 3 | 그림 카드 PNG | 캔버스로 직접 그림: 사진(작게) + 16칸 색 띠 + 곡 제목 + 서비스 이름·주소. `canShare({files})` 되면 공유 시트, 아니면 `<a download>` | 인앱 브라우저는 안내로 대체 | 2차 |
| 4 | 소리 파일(WAV, 모노 16비트, 최대 약 2.4MB — 확인됨) | `LabRender.renderOffline` → `wavBytes`. 굽는 시간 0.3~0.9초(헤드리스 PC, 확인됨. 휴대폰은 미확인) | 위와 같음 | 2차 |
| 5 | 영상 | **넣지 않음** | 형식이 브라우저마다 갈림([04 문서](04-compat.md) 1-3절) | — |

**곡 제목 규칙(초안 — 말투는 사람이 확인):** 앞 낱말 × 뒤 낱말.

| 앞 낱말 | 조건(`gray` → `mode` → `register`) | 뒤 낱말 | 조건(`bpm`) |
|---|---|---|---|
| 고요한 | 흑백 | 자장가 | 72 |
| 반짝이는 | 장조 · 음역 +1 | 오후 | 84 |
| 환한 | 장조 · 음역 0 | 산책 | 96 |
| 포근한 | 장조 · 음역 −1 | 발걸음 | 108 |
| 서늘한 | 단조 · 음역 +1 | 춤 | 120 |
| 잔잔한 | 단조 · 음역 0 | | |
| 깊은 | 단조 · 음역 −1 | | |

- 7 × 5 = 35가지. 시험 그림으로 보면 노을 = "환한 산책"(장조·음역 0·96), 야경 = "깊은 춤"(단조·음역 −1·120), 흑백 = "고요한 자장가"(72) — 야경처럼 어색한 짝이 나오므로 **낱말은 사람이 손본다.** 같은 설정값이면 항상 같은 제목(난수 없음). 받은 쪽도 같은 제목을 본다.
- "당신의 기분은…"처럼 사람을 단정하는 말은 쓰지 않는다([03 문서](03-sonification.md) 7절 원칙).

**링크 미리보기:** 곡 정보가 `#` 뒤에 있어 곡마다 다른 미리보기는 만들 수 없다. 서비스 공통 `og.png` 한 장을 새 방향("사진 → 노래")에 맞게 **다시 만들고**(workspace `qa/og.js`), `index.html` 의 `title`·`description`·`og:*` 문구를 1절의 한 줄 소개로 바꾼다. 하입바이브 카드도 이 그림을 쓴다(workspace `docs/upgrade-plan.md` 공통 약점 1번). 카카오톡 미리보기 갱신 방법은 미확인.

**리뷰·재방문 장치(넣는 것):** ① 곡이 끝나면 "다른 사진은 어떤 노래일까요?" + [다른 사진 넣기] ② 받은 노래 화면의 [내 사진으로도 만들기] ③ 곡 제목(친구와 비교할 거리). 넣지 않는 것: 순위표·계정·서버 저장.

| 아이폰 무음 스위치에서 소리 안 남 | 중간(미확인) | `audioSession` 설정 + 안내 문구 한 줄 |
| 카카오톡 인앱에서 사진 고르기·소리가 막힘 | 모름(미확인) | 예시 그림으로 체험은 됨. 받은 링크 재생은 사진이 필요 없음. 막히면 "다른 브라우저에서 열기" 안내 |
| 기기마다 같은 사진의 곡이 조금 다름(잡음 시험에서 12/14만 같음) | 있음 | 약속을 "같은 기기에서 같은 사진 = 같은 노래, **링크로 보내면 누구에게나 같은 노래**"로 쓴다 |

| 일정 밀림 | 중간 | 뺄 순서: 소리 파일 → 그림 카드 → 붙여넣기·끌어다 놓기 → 곡 제목. **링크 공유와 받은 노래 화면은 빼지 않는다** |

## 11. 이 문서가 정하지 않은 것

- 화면의 색·글꼴·그림체(지금 `core.css`·`style.css` 를 잇는다고만 정함).
- 악기 음색의 최종 수치, 구간 경계의 최종 값(듣고·실제 사진을 넣어 보고 정한다).
- 하입바이브 등록 화면의 항목(카테고리·태그·썸네일 규격) — 접속이 막혀 보지 못했다.
