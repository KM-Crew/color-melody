## 4. 제작 시작 지시문 (다음 작업자에게 그대로 주면 됨)

> **색의 노래 — 사진→소리 본 제작**
>
> 저장소 `KM-Crew/color-melody` 에서 `docs/prep/HANDOFF.md` 와 `docs/prep/BUILD_SPEC.md` 를 먼저 읽고 그대로 만든다. `main` 에서 `feat/photo-song` 브랜치를 만들어 작업하고, 날마다 PR 로 병합한다. 문서·커밋은 한국어.
>
> **지킬 것:** `core.js`·`core.css` 는 고치지 않는다. 사진은 기기 밖으로 보내지 않는다. 로그인·API 키·서버 없음. 남의 사진·음원·코드를 가져오지 않는다. 새 창을 열지 않는다. `Math.random`·`Date` 를 분석·작곡에 쓰지 않는다. 사진 축소 방법(긴 변 512 → 128)을 바꾸지 않는다.
>
> **1단계 — 모듈 옮기기.** `git mv` 로 `lab/analyze.js`·`compose.js`·`render.js`·`seedlink.js` 를 `song/` 으로, `lab/samples/make.js` 를 `song/samples.js` 로 옮긴다. `lab/index.html`·`lab/test/run.js`·`lab/test/browser.js`·`lab/bench/*` 의 경로를 고친다. 검증: `node lab/test/run.js` 46항목 전부 통과, `node lab/test/browser.js` 전부 통과.
>
> **2단계 — 첫 화면과 결과 화면.** 새 파일 `photo.js` 를 만들고 `index.html` 에 `song/*.js` 와 `photo.js` 를 `app.js` 뒤에 넣는다. `app.js` 에서는 `Router.on('/')` 등록과 맨 끝의 `Router.start` 호출만 `photo.js` 로 옮긴다(다른 곳은 건드리지 않는다). BUILD_SPEC 3-1·3-2절대로 첫 화면(사진 고르기 + 예시 그림 3개)과 `#/song`(사진 + 스캔 막대 + 16칸 띠 + ▶ + 설명 카드)을 만든다. `lab/index.html` 의 `pixelsOf`·`ensureCtx`·`play`·`tick` 을 옮겨 쓴다. 방식은 D만.
>
> **3단계 — 공유와 받은 노래.** `LabSeedLink.encode` 로 `#/song?s=…` 링크를 만들고 `shareText` 로 보낸다. `#/song?s=…` 로 열면 `decode` → 사진 없이 색 악보 그림으로 같은 곡을 재생한다(`null` 이면 안내 후 첫 화면). 곡 제목 규칙(BUILD_SPEC 7절)을 넣는다. 빈 상태·오류 상태는 BUILD_SPEC 3-4절 표대로.
>
> **4단계 — 테스트.** 새 화면 테스트 `lab/test/app.js` 를 쓴다(BUILD_SPEC 8-1절 A9~A12: 예시 그림 → ▶ → 링크 복사 → 그 링크로 다시 열어 같은 설정값, 390·520·1280 폭 가로 넘침 0, 외부 요청을 막아도 동작, Space 키, 깨진 링크). workspace 저장소의 `qa/melody.js` 가 계속 통과하는지 본다 — 첫 화면이 바뀌므로 그 테스트의 첫 화면 대기(`.hero`)를 맞춰 준다.
>
> **5단계 — 마무리.** `index.html` 의 제목·설명·`og:*` 문구와 `og.png` 를 새 방향으로 바꾼다. `PLAN.md`(페이지 구성)·`PROGRESS.md`·`README.md` 를 고친다. 시간이 남으면 그림 카드 → 소리 파일 저장 순으로 넣는다(BUILD_SPEC 7절). 11/29 에는 새 기능을 넣지 않는다.
>
> **검증 방법(매 단계):** color-melody 폴더에서 `python3 -m http.server 8791 --bind 127.0.0.1`, 상위 폴더에서 `python3 -m http.server 8790 --bind 127.0.0.1` 을 띄우고 `node lab/test/run.js && node lab/test/browser.js && node lab/test/app.js && (cd ../workspace/qa && node melody.js)`. 전부 통과해야 병합한다. 헤드리스 브라우저는 workspace `qa/launch.js`(`cd workspace/qa && npm install && npm install puppeteer@22`).
>
> **사람에게 넘길 것:** 소리를 귀로 듣는 평가와 실기기 점검(BUILD_SPEC 8-2절 D1~D9)은 자동으로 못 한다. 단계가 끝날 때마다 배포 주소와 함께 "들어 보고 확인할 것"을 적어 남긴다.
